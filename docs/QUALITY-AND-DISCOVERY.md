# Source research and update plan for v0.1.1

Reviewed on November 21, 2026. This atlas answers three separate player questions. What is the objective? Is it available in my save? Where can I start it? Each answer needs its own source. A chapter number can establish when a mission appears. A named county alone cannot identify a street corner.

## How an update reaches a map or a build

1. **Discover.** The local server schedules general discovery and Bounty Watch independently. The default is once a day. Each supports a manual check or a six- or twelve-hour cadence. If a computer is switched off at the scheduled time, the next launch checks the saved due time. Public search can nominate a new publisher. Its own feed must produce an eligible article before it contributes a finding. [Discovery implementation](RESOURCE-DISCOVERY.md)
2. **Qualify.** Check the game, date, topic and acquisition or mission signal. Discard marketing, unrelated titles and vague predictions. Store the public URL, timestamp and short excerpt. Some feeds often have no relevant records. They remain distinguishable from feeds that failed.
3. **Resolve a position.** Accept a documented map marker, a supported venue or an explicit validated game grid. A report with a useful objective and insufficient position evidence stays readable. Do not place it at the center of a region.
4. **Compare.** Group only distinctive activity and location matches. Copies, mirrors and two pages quoting the same evidence cannot provide independent confirmation. Store an explanation beside every single-source, corroborated or disputed report. Corrections can remove an existing pin. [Review rules and thresholds](EVIDENCE-REVIEW.md)
5. **Deliver.** Refresh the open dashboard from the local server. Update category results, mission leads and applicable goals. Preserve completion, player position, personal pins and objective checklists. Remove route stops attached to invalidated positions. Read the rescan time and individual source errors in Live sources.
6. **Recover.** Keep the last usable cache through an outage. Reprocessing the same article updates its existing record. Replaying an unchanged scan does not create another pin or consume another inference request for that article.

## Observed discovery coverage

In an anonymous November 21 validation, the publisher and discovery feeds accepted 41 distinct source URLs. Twenty-three described individual missions. One of those articles gave enough information to locate its start at a named venue. A separate full-index check read 142 direct mission walkthrough links and found zero additions beyond the bundled catalogue at that time. This checker can read up to four new directly linked mission pages per refresh. Its failures leave previous records intact. [Coverage and feed-level results](RESOURCE-DISCOVERY.md)

## Where AI earns its cost

The scanner, publisher discovery, duplicate checks, map registration, evidence labels, route calculation and goal planner all work without inference. Optional AI extracts short, grounded instructions from a new or changed public source. The server validates the quotation and only accepts a venue it can independently map. The model cannot invent an X/Y position or send the scanner to a URL.

Players who choose a provider get a live catalogue. Opaque keys require a provider choice before use. The app never tests a key against multiple providers. Use the free OpenRouter route within its published limits, a local Ollama model, or an explicitly selected metered provider. Provider catalogues and quotas change. ## Release checks

Reproduce a scheduled discovery with an unseen source, an unavailable endpoint, an independently corroborated location and a later conflicting report. Check the resulting pin, evidence links, goal eligibility and route removal in a fresh player session. Exercise real catalogue structure independently of synthetic scanner fixtures. Check a chapter-gated build, completion and undo, backup and restore, and an empty bounty goal. Pack the release and install that archive into a clean prefix. The Windows launcher and npm shims must select an available port and stop only their own instance. Cross-platform runtime coverage is recorded separately.
